europrocessorv4.1

ESP32-S3 기반 아날로그 필름 현상용 로터리 프로세서 제어 펌웨어 전체 설명서. 스테퍼 모터로 현상 탱크를 정/역 교반하고, 약품 온도를 측정하며, 웹 UI와 물리 디스플레이(TFT + 로터리 인코더)로 레시피/수동 운전을 제어한다. 단일 .ino 모놀리식에서 PlatformIO 기반 C++ OOP로 이관(v4.0)된 구조 기준.

개요

이 펌웨어의 설계 목표는 세 가지다.

  • 모터 타이밍 보장 — 스텝 펄스는 하드웨어 ISR(FastAccelStepper)이 독립 생성하고, 상태머신은 Core 1에 격리되어 WiFi·웹·디스플레이 부하와 무관하게 정/역 교반 타이밍을 유지한다.
  • 크로스코어 안전성 — Core 0(웹/UI)은 모터·레시피 상태를 직접 건드리지 않는다. 모든 조작은 CommandQueue로 전달되어 Core 1 단일 코어에서만 상태가 바뀐다. 레이스를 구조적으로 제거.
  • 물리 손상 방지 — 부팅 즉시 모터 EN 차단·패널 핀 idle 고정, 가속/감속 곡선으로 탈조 방지, 플래시 연산과 인코더 인터럽트의 충돌(캐시 panic) 게이팅.
읽는 순서. 하드웨어를 만지는 사람은 1~3·13장, 코드를 보는 사람은 4~9장, API를 쓰는 사람은 10장, 빌드는 12장부터 보면 된다. 9장(크래시 분석)은 이 프로젝트에서 가장 비싸게 배운 교훈이라 따로 떼어 두었다.

속도 계산

출력축 RPM을 모터 step/s로 환산하는 식은 MotionController·Config.h에 동일하게 박혀 있다.

// step/s = 출력RPM × 기어비 / 60 × (200 step × 8 마이크로스텝)
MAX_SPEED = 80 RPM × 3.71 / 60 × 1600  ≈ 7,915 step/s
// S-커브 가감속 — 설정 RPM(v_t)까지 RAMP_SEC=2초, handover f=0.5
a   = v_t·(1+f)/T = 0.75·v_t        // 정가속 구간 가속도
s_h = f²·v_t·T / (1.5·(1+f)) ≈ 0.22·v_t  // 저크제한(소프트스타트) 스텝수
  • 출력 80RPM = 모터 약 297RPM = 7,915 step/s (MAX_SPEED 상한).
  • 80 초과 시 탈조는 코드 결함이 아니라 토크–속도 한계(back-EMF). 권장 운전 75RPM.
  • 하한 MIN_OUTPUT_RPM=5 — 실속(stall) 방지.

교반 시나리오

정방향 rotIntSec 구동→ 감속 정지→ REST 2초 (EN=HIGH, 코일 차단)→ 역방향 구동→ …

무한 반복. REST 구간(REST_MS=2000)에 TMC2209 EN을 HIGH로 올려 코일 전류를 끊어 관성을 안정시키고 발열을 억제한다. REST는 가속도 곡선 감속이 완전히 끝난 뒤 시작하므로 2초는 순수 휴식 구간이다. 레시피 모드에서는 각 단계가 속도 / 지속시간 / 방향전환주기를 개별로 가진다.

MotionController — 모터 상태머신

FastAccelStepper로 펄스를 생성하고 EN 핀은 수동 제어(REST 구간 코일 차단). 레시피를 모른다 — 단계 종료는 requestStepStop()으로 받고, 감속 완료는 takeStepStopped() 이벤트로 알린다. 모든 상태 변경은 Core 1에서만.

S-커브 가감속. beginRun()은 applyRamp(목표속도)를 호출해 설정 RPM마다 가속도와 저크제한 구간(setLinearAcceleration)을 다시 계산한다. 가속도가 0에서 선형으로 증가하는 소프트스타트라 출발/정지가 부드럽고, 어떤 설정 RPM이든 도달 시간이 RAMP_SEC(2초)로 일정하다. setLinearAcceleration은 stopMove() 감속에도 적용되어 정지도 대칭으로 부드럽다. (11장 상수)

API설명
beginRun(rpm,fwd)출력축 RPM·방향으로 구동 시작
stopImmediate()비상: forceStop + EN 차단 + IDLE (targetRpm=0)
freeze()일시정지: halt + EN 차단 + IDLE (targetRpm 유지)
requestSafeStop()가속도 곡선 감속 후 IDLE
requestStepStop() / takeStepStopped()레시피 단계 종료 감속 요청 / 완료 1회성 이벤트
state() · curRpm() · targetRpm() · isFwd() · cycle()상태 조회 (const)

RecipeRunner — 레시피 시퀀서

steps 벡터를 뮤텍스로 보호(웹 buildStatus가 Core 0에서 동시 읽기)하며, 모터는 MotionController 경유로만 구동한다.

load() → startStep(0) → 단계 지속시간 경과 시 requestStepStop()
       → 감속 완료(takeStepStopped) → waitConfirm(약품 교체 대기)
       → confirm() → 다음 단계 …

그 외: pauseToggle() · skipStep()(현재 단계 건너뜀) · snapshot()(표시용 상태 스냅샷, 뮤텍스 밖 안전 사용).

TemperatureSensor — 온도 측정

Core 0 전용 태스크에서 MAX31865를 1Hz 폴링(소프트웨어 SPI). 모터 코어에 영향 없음. fault는 즉시 clear하지 않고 연속 5회 누적 후에만 시도 → 단선/접촉불량을 UI에서 끊김 없이 관찰.

  • 결선 모드: Cfg::RTD_WIRES(2/3/4) — 보드 솔더점퍼와 일치 필수.
  • 진단: 부팅 시 threshold 레지스터 SPI 라운드트립 자가진단(칩·통신 검증) + fault 비트 디코드 + raw RTD 출력.
  • 격리: TEMP_SENSOR_PRESENT=false면 init·폴링 태스크 미생성 → temperature()=TEMP_UNREAD, fault 없음(디스플레이 --.-). 현재 센서 보드 불량으로 격리됨 — 양품 장착 시 true 복귀.

WifiManager — 네트워크

AP+STA 동시 모드. AP http://192.168.4.1, mDNS http://europrocessor.local, AP DNS(captive). STA 자동 재연결 이벤트 처리. 설정은 Preferences wifi 네임스페이스에 영구 저장.

WebServer — HTTP

ESPAsyncWebServer 기반. HTML은 web_assets.h에 PROGMEM 임베드. 의존성(motion/recipe/temp/cmd/wifi/saver)을 begin()에서 주입받아 소유하지 않는다. 대용량 JSON(/api/start, 레시피 저장)은 청크 분할 수신 + reserve로 힙 단편화를 억제. 화면보호기 업로드는 파일핸들(_upFile)을 한 번 열고 청크마다 write만 한다.

DisplayUI — 물리 UI

ST7789 320×240 + EC11 인코더 + KO 버튼. U8g2로 한글 UTF-8 폰트 출력. 캐시 기반 부분 렌더링으로 깜빡임 제거. initTft에서 invertDisplay(false)로 패널 색반전 보정(이 패널은 INVON이 색을 네거티브로 반전). ISaver를 구현해 웹에서 화면보호기 설정을 읽고 쓴다.

페이지: STATUS / 레시피경고 / 수동메뉴 / 속도·주기·화면보호기시간 편집 / 정보 / 화면보호기. (자세한 화면보호기 동작은 8장)

IDLE정지
RUN_FWD / RUN_REV정 / 역방향 정속
STOP_FWD / STOP_REV해당 방향 감속 → REST
REST방향전환 휴지 — EN=HIGH (코일 전류 차단, 관성 안정 + 발열 억제), REST_MS=2000
STOP_RECIPE레시피 단계 종료 감속 → waitConfirm
STOP_SAFE안전 정지 감속 → IDLE (다음 사이클 없음)
cycle 플래그. setCycle(false)면 한 방향 구동 후 자동 방향전환을 하지 않는다. 수동 운전에서 단방향 회전이 필요할 때 사용.

7레시피 실행 흐름

레시피는 StepInfo 배열(name / speedRpm / durSec / rotIntSec)이다. 웹에서 시작하면 곧장 실행되지 않고 스테이징을 거친다.

[Core 0] 웹 POST /api/start     →  stage.stage(name, steps)   // 뮤텍스 버퍼 적재만
[Core 1] loop()                  →  stage.consume()            // 안전한 시점에 꺼냄
                                →  stopAll() + recipe.load()  // 기존 정지 후 0단계 실행

각 단계:  startStep(idx) → durSec 경과 → requestStepStop()
          → takeStepStopped() → waitConfirm → confirm() → 다음 단계
  • waitConfirm — 단계 사이에 약품 교체를 위해 사용자 확인을 기다린다. 웹 /api/confirm 또는 디스플레이 OK.
  • skipStep — 확인대기 여부와 무관하게 현재 단계를 건너뛰고 다음으로.
  • pauseToggle — 진행 중 일시정지/재개. 경과시간 보정.

8화면보호기 파이프라인

온디바이스 GIF 디코드(AnimatedGIF)는 이 빌드에서 실패했다(프레임1 부분 + err=1, 파일/RAM open 무관). 따라서 라이브러리와 관련 코드를 전부 제거하고, 브라우저에서 사전 인코딩한 RGB565 프레임을 기기는 디코드 없이 blit하는 방식으로 전환했다.

업로드 경로 — 브라우저 트랜스코드

[브라우저 web_assets.h]

[기기 DisplayUI.cpp]

.anim 포맷 (ANM1)

오프셋크기내용

기기는 loadAnim()에서 12 + frames×W×H×2 == 파일크기를 검증하고 PSRAM(ps_malloc)에 통째로 올린다. 검증 실패 시 모든 경로에서 free.

우선순위

① /saver.anim (업로드 애니)> ② /saver.jpg (정적 JPEG)> ③ 임베드 Nyan (기본)

임베드 Nyan은 tools/gen_nyan.py가 생성한 nyan_frames.h(160×120×12, flash 상수, RAM 0). 무압축 RAW이므로 용량 = dims×frames×2 (색 무관) — 줄이려면 frames/dims를 줄인다.

전원 OFF 시 유지. 업로드한 /saver.anim·/saver.jpg는 LittleFS에 영구 저장되어 재부팅해도 유지된다. 삭제는 DELETE /api/saver/image.

9크래시 분석 & 방지

증상. 모터 회전 중 화면보호기 진입·이미지 업로드·삭제 시 간헐적 Guru Meditation Error: Cache disabled but cached memory region accessed (Core 1 panic, reset reason 4). 처음엔 브라운아웃으로 오진했으나 WiFi 미사용 중에도 발생 → panic 확정.

근본 원인

LittleFS 읽기/쓰기·WiFi NVS 같은 플래시 연산은 순간 캐시를 끈다. 그 창에 ISR이나 코드가 플래시 영역(.rodata, 플래시 상주 함수)을 건드리면 패닉한다. 여기서는 모터 EMI로 유발된 인코더 GPIO 인터럽트가 그 트리거였다.

충돌 시나리오
모터 회전 → EMI → 인코더 핀 엣지 → encISR 발생
          ↘ 그 순간 화면보호기 loadAnim()이 LittleFS read 중 (캐시 OFF)
          → ISR/디스패처가 플래시 접근 → Cache disabled panic

적용한 방어

계층조치
ISR IRAM-safe화encISR이 REG_READ(GPIO_IN_REG) 직접 읽기 + DRAM_ATTR 디코드 테이블 사용 (플래시 함수·.rodata 회피)
플래시op 게이팅
(최종 차단)		모터 비-IDLE이면 모든 플래시 연산 금지:
· 화면보호기 진입/렌더 안 함 (loadAnim 차단)
· 업로드 시작 거부 + 진행 중 모터 기동 시 중단·부분파일 삭제
· 삭제 409 응답
왜 PCNT 인코더로 안 바꿨나. 하드웨어 PCNT 카운터로 옮기면 ISR 자체를 없앨 수 있지만, FastAccelStepper가 ESP32-S3 스텝 생성에 PCNT(MCPWM_PCNT)를 점유한다. 인코더용 PCNT가 모터와 충돌해 둘 다 깨졌다 → 인터럽트 인코더 유지 + 게이팅으로 결론.
새 ISR/플래시op 추가 시 원칙. ① ISR은 IRAM-safe(IRAM_ATTR 함수 + DRAM_ATTR 데이터 + 레지스터 직접 접근). ② LittleFS/NVS 등 플래시op는 모터 IDLE일 때만 수행.

13안전 설계 (물리 손상 방지)

  • 부팅 즉시 TMC2209 EN=HIGH — 리셋~setup 구간 floating으로 코일이 통전된 채 정지하면 발열/소손. 권장 HW 풀업: EN→3.3V 10K.
  • 부팅 즉시 패널 신호 핀 idle 고정 — floating noise가 패널 컨트롤러를 비정상 state로 몰아 ESD/latch-up 손상 누적 방지. 권장 HW 풀업: TFT CS·RST→3.3V 10K.
  • 디스플레이 배선 주의 — 신호선을 5V(VBUS) 근처로 라우팅하지 말 것. 5V가 신호핀에 닿으면 내부 ESD 다이오드를 통해 VCC 레일로 역주입되어 컨트롤러/백라이트가 손상될 수 있음 (실손상 사례 있음).
  • 탈조 방지 — 모든 시작/정지/방향전환은 AccelStepper 가속도 곡선 경유. 비상정지(stopImmediate)만 즉시 정지.
  • 냉각 — 75RPM 연속 2h+ 시 모터·전자부 ≈50°C(실측). 발열은 I²R 지배 → VREF 최소 유지 정책.
